## 3. 챗봇 속도 (#266)

**목표**: 질문 버튼은 기다림 없이, 직접 친 질문은 3~5초 안에

| 무엇 | 전 | 후 |
|---|---|---|
| 질문 버튼 | 제미나이가 붐비면 20~36초 | **바로** (AI 없이 미리 계산해 둔 값으로 답) |
| 직접 친 질문 | 10초 이상 · 가끔 실패 | **평균 1.8초**, 가장 느린 것 5.3초 |

**어떻게**
- 버튼 답은 AI를 부르지 않고 정해진 틀에 도구 값만 넣음 (`chat/quick.py`)
- 질문을 보고 꼭 필요한 자료를 미리 불러 AI에게 같이 줌 → AI가 자료를 부르러 오가는 횟수가 줄어듦
- 질문을 받을 담당(시세 · 원가 · 내일 준비)을 낱말로 바로 고름 → 담당 고르는 AI 호출 1~1.7초 절약
- **Groq 무료 모델**을 먼저 쓰고, 막히면 제미나이로 (`CHAT_PROVIDER=groq`)
  - Groq: 모델마다 분당 8,000토큰 · 하루 1,000번 무료. `gpt-oss-120b` → `qwen3.8-27b` → `gpt-oss-20b` 차례
  - 제미나이 무료는 flash 모델마다 하루 20번뿐이라 금방 바닥남
- 한도에 걸린 모델은 잠시 건너뜀, 10초 넘게 답이 없으면 다음 모델로
- 서버가 켜질 때 시세 · 원가 · 내일 준비 자료를 미리 불러 둠

**병목 점검**: 담당(에이전트) 셋은 분리된 대로 돌아감. 섞인 질문은 담당들을 동시에 부름(차례로 부르면 두 배 걸림)

## 4. 영수증 (#267)

- **여러 장 찍기 서버**: 긴 영수증을 나눠 찍은 사진 여러 장을 한 번에 받아 한 영수증으로 읽음 (`images` 목록). 화면은 팀원이 만들 예정
- **읽기 속도**: 붐비는 모델을 25초 넘게 기다리지 않고 다음 모델로, 실패한 모델은 잠시 건너뜀
- **같은 사진은 바로**: 한 번 읽은 사진은 결과를 보관해 두고 다시 올리면 0.7~1초
- **영수증 목록**: 10분 동안 보관해 두고 다시 씀 → 화면이 바로 뜸

## 6. 예측 정답률 (#269)

**문제**: 전체 방향 정답률 58.5% — 찍어도 50%라 너무 낮음 (목표 70%)

**원인 (오답노트)**: 하루하루 값은 흔들림이 커서 "내일 오를까"는 맞히기 어려움. 틀린 예측 상당수가 변화가 아주 작은 날

**바꾼 것**
- 맞히는 대상: 내일 값 → **다음 주 평균 ÷ 이번 주 평균** (모델 이름 `ai-week-…`)
- **자신 있을 때만 방향을 말함**: 4% 넘게 움직일 것 같을 때만 "오를 것 / 내릴 것", 아니면 "비슷할 것" (`direction_code`: up / down / unsure)
- 화면 문구: "다음 주 평균 약 …"

**결과 (방향을 말한 예측만)**

| 분류 | 정답률 | 방향을 말한 비율 |
|---|---|---|
| 야채 | **71.7%** | 61% |
| 과일 | **70.5%** | 37% |

- 시중 모델도 비교함: 시계열 모델(Chronos 등), 표 데이터 모델(LightGBM · 신경망 등) → [1125_direction_accuracy.md](forecast/1125_direction_accuracy.md)
- 매일 아침 6시 학습은 그대로 돌아감. 새 모델이 정반대 예측을 0.3%p 이상 줄이고 평균 오차가 나빠지지 않을 때만 교체

## 7. 영수증 Groq · 악용 막기 (#271, 배포 확인)

조건: **무조건 무료 안에서**, 이미 배포된 사이트라 악용 대비

**영수증 처음 읽기**
- Groq 무료 사진 모델 `qwen/qwen3.8-27b`로 먼저 읽고 막히면 제미나이
- 처음 읽기 8~20초 → **2~4초**. 시연 영수증 20장 중 끝까지 읽은 18장 모두 정답 (줄 · 금액 · 재료 · 날짜 · 합계)
- 한계: Groq 무료는 1분에 영수증 약 3장. 넘으면 제미나이로 넘어가 느려짐

**악용 막기 — 접속한 곳(IP)마다 횟수 제한**

| 무엇 | 1분에 | 하루에 |
|---|---|---|
| 챗봇 직접 질문 (버튼은 안 셈) | 8번 | 150번 |
| 로그인 없이 영수증 읽기 | 3번 | 15번 |
| 로그인한 사장님 영수증 읽기 | 6번 | 60번 |
| 영수증 저장 | 6번 | 60번 |

- 넘으면 "요청이 너무 많아요. 잠시 뒤 다시 해 주세요"가 화면에 뜸
- 한계: 서버(Vercel)가 여러 대면 서버마다 따로 셈. 악용이 실제로 보이면 데이터베이스로 세도록 바꿀 것

**배포 뒤 실제 사이트 확인**
- Vercel에 `GROQ_API_KEY` 들어감 확인 (영수증 답에 Groq 이름이 찍힘)
- 영수증 3.3~6.2초, 챗봇 1.7~3.2초
- 배포 직후 첫 챗봇 질문만 55초 (서버가 켜지며 자료를 불러오는 시간). 시연 전에는 질문을 하나 던져 둘 것

## 8. 챗봇 말투 · 살피 소개 · 대화 이어서 이해 (올리기 전)

바뀐 파일: `salpi_agent/chat/agent.py`, `salpi_agent/chat/quick.py`

**답에 나오면 안 되는 것**
- 영어 낱말 (`confidence` 등) → 우리말로. 원인: AI 지시문에 영어가 섞여 있어서 따라 씀
- `₩` 기호 → "1,187원"처럼
- "다른 살피 담당이 알려드릴게요" → 삭제. 넘겨받아 답하는 기능이 없어서 말만 하고 끝났음

**살피 소개 — AI 없이 정해진 답 (0초)**

| 물으면 | 답 |
|---|---|
| 이름 · 뜻 · 누구야 | 저는 시장의 원가율과 마진, 시장 시세를 살핀다는 뜻의 미어캣 살피예요. 궁금한 점이 있으시면 언제든 물어봐 주세요. |
| 몇 살 · 나이 | 저는 3살이에요. |
| 키 | 키는 약 35cm예요. |
| 몸무게 | 몸무게는 약 0.7~1kg이에요. |
| 엄마 · 부모님 | 엄마는 대구에 사는 '살피맘'이에요. |
| 고마워 · 감사 | 감사합니다! 언제든지 원가·마진, 시세 계산이 필요하시면 알려드릴게요. 좋은 하루 보내세요. |
| 안녕 | 안녕하세요, 사장님! 살피예요. 시세 · 원가 · 내일 준비량, 궁금한 걸 물어봐 주세요. |

- 15자 이하의 짧은 질문이면서 시세 · 원가 낱말이 없을 때만 정해진 답 ("키위는?", "양파 고마워 근데 오를까"는 제외)
- 식당과 상관없는 질문 ("오늘 축구 누가 이겼어?")은 할 수 있는 일과 질문 예시를 안내

**대화 이어서 이해하기** — "내 비빔밥 뭐가 문제야" → "그럼 김치찌개는?"이 엉뚱한 답이 된 원인과 고친 것

| 원인 | 고친 것 |
|---|---|
| 담당을 고를 때 지금 질문만 봄 → "김치찌개는?"이 시세 담당으로 감 | 짧게 이어 물으면 앞 질문의 담당 그대로. 앞 질문에 단서가 없으면 살피의 앞 답에서 고름. 담당 고르는 AI에도 앞 질문을 같이 줌 |
| 메뉴 이름이 낱말 규칙에 없음 | 찌개 · 볶음 · 비빔밥 · 제육 · 떡볶이 등은 원가 담당으로. "내일 김치찌개 몇 그릇"은 내일 준비 담당 |
| 짧은 질문엔 가게 원가표를 미리 안 불러 AI가 숫자를 지어냄 (제육 43.8%, 판매가 25,000원 — 실제는 41.5%) | 원가 담당은 항상 가게 원가표를 먼저 불러옴 |
| 가게 메뉴에 없는 비빔밥을 제육볶음 숫자로 바꿔 말함 | "우리 가게 영수증 메뉴에는 비빔밥이 없어요"라고 말하고 있는 메뉴 안내 |

**고친 뒤 시험 (실제 AI)**
- 비빔밥 → "메뉴에 없어요" / 김치찌개 → 원가율 20.2%, 7,179원 남음 (6.8초) / 제육 → 41.5%, 9,500원으로 올리면 39.4% (1.2초)
- 숫자 검사: 답의 숫자가 모두 실제 자료 값과 일치

**한계**
- 영어 · ₩ · "다른 담당" 금지는 AI 지시라 100% 막지는 못함 (시험에서는 0번)
- 지난 대화는 최근 6번 주고받은 것까지 AI에게 전달
