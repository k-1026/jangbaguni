## 1. 브랜드 페르소나 vs 고객 페르소나

두 페르소나는 **방향이 반대**입니다. 브랜드 페르소나는 "우리가 어떤 존재로 말하는가", 고객 페르소나는 "누구에게, 어떤 상황에서 말하는가"를 정합니다.

| 구분 | 브랜드 페르소나 | 고객 페르소나 |
|---|---|---|
| 질문 | 우리는 누구이고 어떻게 말하는가 | 누가, 왜, 언제 우리를 쓰는가 |
| 기준 | 핵심 자산(캐릭터·색·핵심 문장)과 가치 | 구매 행동, 불편, 목표 |
| 결과물 | 페르소나 시트, 톤 가이드, 금칙어, 브랜드 스킬 파일 | 페르소나 카드, 세그먼트 정의, 여정 |
| 바뀌는 정도 | 거의 고정 (일관성이 자산) | 데이터가 쌓이면 계속 수정 |
| 이 프로젝트 | **살피** — 시세를 살피는 미어캣 | **대구 외식업 사장님** 외 2그룹 |

**연결 규칙**: 살피의 말투는 하나로 고정하고, 세그먼트에 따라 **무엇을 먼저 말할지(메시지 우선순위)** 만 바꿉니다. 예: 시세 민감형에게는 가격 알림을, 루틴 고정형에게는 "평소보다 3kg 더"처럼 차이를 먼저 말합니다.

## 2. 고객 페르소나 3종

PPT 4장 '대구의 구매자 세 그룹'을 사람 단위로 구체화했습니다. 근거 수치는 PPT 조사 출처(KREI 외식업체 경영실태조사 등)를 그대로 사용했습니다.

### P1. 메인 — 대구 달서구 한식당 사장님 "박정숙(가상, 54세)"

| 항목 | 내용 |
|---|---|
| 가게 | 30석 한식당, 김치찌개·제육볶음·된장찌개 주력, 배달 병행 |
| 구매 방식 | 개인 도매상·식자재마트에서 주 1~2회, 예상 손님 수만큼 소량 구매 |
| 가격 판단 | 거래처가 부르는 값을 그대로 받음. 공공 시세(KAMIS 등)는 보지 않음 (전체의 4.8%만 참고) |
| 수량 판단 | "지난주 금요일만큼" 경험과 감 |
| 불편 | 식재료비가 매출의 40% 이상. 비 오는 금요일에 돼지고기가 모자라거나, 양파가 남아 버림 |
| 목표 | 원가율을 지키면서 재료가 떨어지는 날을 줄이는 것 |
| 디지털 수준 | 카카오톡·배달앱은 익숙, 엑셀·대시보드는 부담 |
| 살피에게 바라는 한마디 | "그래서 내일 몇 kg 사면 되는데?" |

### P2. 서브 — 소규모 단체급식 영양사 "이지은(가상, 37세)"

| 항목 | 내용 |
|---|---|
| 업무 | 대구 산업단지 내 1일 300식 위탁급식 |
| 구매 방식 | 식단 단위 대량 발주, 납품 일정 고정 |
| 불편 | 계약 단가는 못 올리는데 식재료값은 오름 (대형 급식사 영업이익률도 약 5%) |
| 목표 | 식단 확정 전에 가격이 오를 품목을 미리 알고 대체 식단 짜기 |
| 살피에게 바라는 한마디 | "다음 주 식단에서 위험한 품목만 알려줘." |

### P3. 서브 — 식자재 구매·재고 담당 "최민호(가상, 41세)"

| 항목 | 내용 |
|---|---|
| 업무 | 프랜차이즈 2~3개 매장 구매·납품·재고 운영 |
| 불편 | 매장마다 재고가 들쭉날쭉, 과잉 재고와 결품이 동시에 발생 |
| 목표 | 매장별 적정 발주 시점과 재고 경고 |
| 살피에게 바라는 한마디 | "어느 매장이 언제 떨어지는지 먼저 알려줘." |

## 3. 행동 데이터 기반 고객 세그먼트 정의 (중요)

### 3-1. 왜 '행동'으로 나누는가

업종·매장 규모 같은 **속성**으로 나누면 "같은 한식당인데 왜 반응이 다른가"를 설명하지 못합니다. 이 서비스의 성과(결품↓, 폐기↓, 원가율 유지)는 **사장님이 알림과 추천에 어떻게 반응하는가**에 달려 있으므로, 행동 지표로 나누고 속성은 보조 정보로만 붙입니다.

출발점은 가장 널리 쓰이는 **RFM(최근성·빈도·금액)** 모델입니다. RFM은 정보가 적어도 쓸 만한 세그먼트를 만들 수 있다는 장점이 있지만, B2B에서는 구매 품목의 다양성(Variety)을 더하면 고객을 더 정확하게 이해할 수 있다는 연구가 있어 **RFM + V**에 이 서비스 고유의 반응 지표를 더합니다.

### 3-2. 5단계 정의법

| 단계 | 할 일 | 이 프로젝트에서의 실행 |
|---|---|---|
| ① 이벤트 정의 | 앱에서 기록할 행동을 정함 | 아래 3-3 이벤트 로그 |
| ② 지표 산출 | 매장 1곳 × 기간(최근 8주) 단위로 지표 계산 | 아래 3-4 지표 표 |
| ③ 점수화·군집화 | 지표별 1~5점(5분위) → 규칙 기반 분류, 데이터가 쌓이면 K-means | 처음엔 규칙, 이후 실루엣 계수로 군집 수 결정 |
| ④ 이름·해석 | 군집마다 "어떤 사장님인가"를 한 줄로 | 3-5 세그먼트 5종 |
| ⑤ 액션 연결 | 세그먼트별 살피의 메시지·알림 정책 | 3-6 액션 표 |

### 3-3. 기록할 행동 이벤트 (로그 설계)

| 이벤트 | 기록 항목 |
|---|---|
| `forecast_view` | 예측 화면 조회 시각, 메뉴 |
| `order_recommend_shown` | 추천 품목, 추천 수량 |
| `order_placed` | 실제 발주 품목·수량·금액·구매처(식봄/마트/도매상) |
| `alert_sent` / `alert_clicked` | 알림 종류(가격 급등·원가율·기다리기), 클릭 여부, 반응 시간 |
| `stockout_report` | 재료 소진 신고(품목, 시각) |
| `waste_report` | 폐기 입력(품목, kg) |
| `deeplink_click` | 판매처 검색 이동 여부(어느 판매처) |
| `receipt_upload` | 영수증 촬영 여부, OCR 인식 품목 수 |
| `menu_action_accept` | 메뉴 가격 조정·대체 재료 제안 수락 여부 |
| `feedback_rating` | 발주 추천 별점 (PPT 07장 평가 화면) |

### 3-4. 세그먼트 지표 (RFM + V + 서비스 반응)

| 코드 | 지표 | 계산 |
|---|---|---|
| R | 최근성 | 마지막 발주 후 경과 일수 |
| F | 빈도 | 8주간 주당 평균 발주 횟수 |
| M | 금액 | 8주간 평균 주간 발주액 |
| V | 품목 다양성 | 8주간 발주한 서로 다른 품목 수 |
| C | 주기 규칙성 | 발주 간격의 변동계수(표준편차÷평균). 낮을수록 규칙적 |
| A | 추천 수용률 | 실제 발주량이 추천량 ±10% 안에 든 비율 |
| P | 가격 반응도 | 가격 알림 클릭률 + '기다리기' 후 발주 연기 비율 |
| E | 긴급 발주율 | 재료 소진 신고 후 24시간 안 발주 비율 |

### 3-5. 세그먼트 5종 (초기 규칙 기반)

| 세그먼트 | 행동 규칙 (초기 기준, 가상) | 주로 해당하는 페르소나 |
|---|---|---|
| **S1 시세 민감 알뜰형** | P 상위 20%, F 주 2회 이상 | P1 일부 |
| **S2 루틴 고정형** | C 낮음(규칙적), A 하위 40% — 추천을 보지만 늘 같은 양 | P1 다수 |
| **S3 대량 계획형** | M 상위 20%, F 주 1회 이하, V 높음 | P2 |
| **S4 급발주 위험형** | E 상위 20% 또는 소진 신고 주 1회 이상 | P1·P3 |
| **S5 이탈 위험형** | R이 평소 발주 간격의 2배 초과, 예측 조회 감소 | 전 그룹 |

한 매장이 두 조건에 걸리면 **S5 → S4 → S1 → S3 → S2** 순으로 우선 적용합니다(손실이 큰 순서).

### 3-6. 세그먼트별 살피의 액션

| 세그먼트 | 살피가 먼저 말할 것 | 알림 정책 | 성공 지표 |
|---|---|---|---|
| S1 | "양파, 오늘보다 다음 주가 쌀 확률이 높아요" | 가격 알림 우선, 기다리기 알림 허용 | 구매 단가 / 도매 시세 격차 |
| S2 | "평소보다 돼지고기 3kg 더 필요해요" (차이만) | 평소와 다를 때만 알림 → 알림 피로 방지 | 추천 수용률 A 상승 |
| S3 | "다음 주 식단 중 가격 위험 품목 2개" | 주 1회 요약 리포트 | 식단 확정 후 단가 변동 |
| S4 | "금요일 비 예보, 제육볶음 재료 오늘 미리" | 전날 오후 선제 알림 | 결품 일수 E 감소 |
| S5 | "지난주 김치찌개 예측, 이만큼 맞았어요" | 성과 요약 1회, 과도한 알림 중단 | 재방문, R 회복 |

### 3-7. 검증 방법

- PPT 07장 비교 기준(지난주 같은 요일 / 일반 ML / 고정량 주문)과 **세그먼트별로 따로** 결품 일수·폐기량·구매 단가를 비교합니다.
- 실데이터가 없는 시연 단계에서는 가상 매장 데이터에 세그먼트 5종의 행동 패턴을 심어 백테스트합니다.
- 실데이터 확보 후 규칙 기반 분류와 K-means 군집 결과가 얼마나 겹치는지 확인하고, 실루엣 계수로 군집 수를 다시 정합니다.

### 4-2. 시트 1 — 기본 포즈 ↔ 앱 상황 매칭

### 4-2-2. 살피 이미지 시트 2 — 기능 소품 포즈 6종

![살피 이미지 시트 2 — 알람시계·경광등·지시봉·쇼핑백 소품 포즈](<미어캣살피_캐릭터/살피의 여섯 가지 알림과 쇼핑 포즈.png>)

시트 2는 **소품으로 기능을 알려주는** 포즈입니다. 시트 1이 감정(놀람·고민·졸림)을 표현한다면, 시트 2는 "어떤 종류의 알림인지"를 소품만 보고 알 수 있게 합니다.

| 시트 2 위치 | 포즈 · 소품 | 앱 기능 | 살피 대사 예시 |
|---|---|---|---|
| 1행 1열 | 머리 위 알람시계 + 검지 들기 | 발주 마감 시간 리마인더 | "내일 아침 받으려면 오늘 주문 마감 시간을 확인하세요." |
| 1행 2열 | 머리 위 빨간 경광등 + 놀람 | 가격 급등 경보 | "대파 도매가가 지난주보다 크게 올랐어요." |
| 1행 3열 | 알람시계를 품에 안기 | '기다리기' 알림 (지금 말고 나중에 사기) | "양파는 다음 주까지 기다려도 괜찮아요." |

| 2행 2열 | 지시봉으로 가리키기 | 추천 이유 설명 ("왜 12kg?") | "금요일 효과가 가장 커요. 같이 볼까요?" |

**색 규칙**: 경광등 빨강은 **경고(급등·원가율)** 에만, 알람시계 민트는 **시간(마감·기다리기)** 에만, 쇼핑백 화살표 민트는 **하락·구매**에만 씁니다. 같은 색을 다른 뜻으로 쓰지 않아야 사장님이 소품 색만 보고 알림 종류를 구분합니다.

**사용 시 주의**: 시트 2는 어두운 배경에 빛 번짐 효과가 있어 그대로 앱에 넣으면 흰 화면에서 테두리가 지저분하게 보입니다. 앱·알림용은 배경 제거 후 PNG로 쓰고, 어두운 배경 효과는 발표 표지·영상 썸네일에만 씁니다.

| 항목 | 정의 |
|---|---|

## 5. 세계관 설계 프레임

### 배경
대구 북구의 새벽 공영도매시장. 경매가 끝나는 새벽 시간, 지붕 위에서 시장 전체를 내려다보는 망루가 살피의 자리입니다. 아침 7시가 되면 살피는 칠판에 오늘 시세를 그리고, 동네 식당 사장님들의 휴대폰으로 소식을 전합니다.

### 인물
| 인물 | 역할 |
|---|---|
| 살피 (주인공) | 시세 파수꾼. 도매시장 숫자를 메뉴 언어로 바꿔 전함 |
| 사장님들 (고객) | 메뉴를 고민하는 대구의 식당·급식 사장님. 세계관의 진짜 주인공 |
| 시장 (환경) | 날씨·명절·반입량에 따라 출렁이는 존재. 적이 아니라 읽어야 할 대상 |

### 갈등
| 층위 | 갈등 |
|---|---|
| 외부 | 들쭉날쭉한 시세, 비·명절·행사로 갑자기 바뀌는 손님 수 |
| 구조 | 가격은 거래처에, 수량은 경험에 의존 → 모자라면 못 팔고, 남으면 버림 |
| 내부 | "이 숫자를 믿어도 될까?" — 사장님의 불신이 가장 큰 벽 |

### 가치
1. **정직한 숫자** — 예측은 항상 범위와 함께, 모르면 모른다고 말함
2. **이유 있는 추천** — "왜 12kg인지"를 같이 보여줌
3. **사장님의 시간** — 하루 한 화면, 30초 안에 결정

### 톤앤매너
| 축 | 위치 |
|---|---|
| 귀여움 ↔ 전문성 | 겉모습은 귀엽게, 숫자는 전문적으로 |
| 친근함 ↔ 격식 | 친근한 존댓말 |
| 긴장감 ↔ 안심 | 경고도 해결책과 함께 → 안심 쪽 |
| 시각 | 니들펠트 질감, 따뜻한 오렌지 + 칠판 다크그린, 손그림 차트 |

# 살피 브랜드 스킬

## 정체성
- 서비스: 살피 — 대구 외식업 사장님을 위한 메뉴 원가 관리 AI (판매 예측·원가율·발주량·메뉴 제안, 아무것도 팔지 않음)
- 캐릭터: 살피. 새벽 도매시장을 먼저 살피고 숫자를 쉬운 말로 전하는 미어캣

## 톤
- 앱 대사: 존댓말 "~해요"체, 한 문장 25자 안팎, 한 알림에 정보 1개
- 숫자: 단위 필수(kg, 원, %, 그릇). 예측은 범위 함께 (예: 120그릇, 95~148)
- 구조: [무엇이] → [얼마나] → [그래서 어떻게] 순서
- 경고 뒤에는 반드시 행동 제안 1개

## 핵심 메시지 3개
1. 얼마 남는지 — "오늘 제육볶음 한 그릇 원가, 매일 계산해 드려요"
2. 얼마나·언제 살지 — "필요한 양은 메뉴로, 살 때는 시세로 판단해요. 기다리는 게 나으면 기다리라고 말해요"
3. 왜 그런지 — "추천에는 항상 이유가 붙어요"
4. 중립 — "살피는 아무것도 팔지 않아요"

## 금칙어 / 금지 표현
| 금지 | 이유 | 대신 |
|---|---|---|
| 무조건, 100%, 확실히, 보장 | 예측은 확률 | "~할 가능성이 높아요" |
| 최저가 보장, 제일 싸요 | 검증 불가·과장 | "도매 시세보다 ○% 낮아요" |

| 대박, 개이득, ㅋㅋ, 이모지 남발 | 신뢰 저하 | 캐릭터 포즈로 감정 표현 |
| 식봄 외 경쟁 플랫폼 비방 | 협업 구조 | 사실 비교만 |
| 출처 없는 통계 | 정직한 숫자 원칙 | 출처·기준 연도 표기 |

### 8-2. '살피'를 앱 이름으로 쓸 때 장단점

| 장점 | 단점 · 대응 |
|---|---|
| 캐릭터 = 앱 이름 → 알림이 오면 "살피가 알려줬다"로 기억됨. 이름과 캐릭터를 따로 홍보할 필요가 없음 | 이름만으로 '식자재 앱'인지 알 수 없음 → 스토어 이름에 설명어("식자재 시세·발주 비서")를 반드시 붙임 |
| '살피다'(자세히 살펴보다)라는 뜻이 서비스 역할(시세 감시)과 정확히 맞음 | 서울시의 1인가구 안부 확인 앱 '서울 살피미'가 이미 있음 → 분야가 달라 혼동 가능성은 낮지만, 검색 노출에서 섞일 수 있음 |
| 두 글자라 50대 사장님도 부르기 쉬움 ("살피 열어 봐") | 상표 등록 여부 미확인 → 제출 전 KIPRIS(특허정보검색서비스)에서 '살피' 지정상품(앱·소프트웨어, 식자재 유통) 검색 필요 |
| 식자재몰 이름과 겹치지 않아 "식자재몰은 어디서 싸게, 살피는 얼마 남을까" 포지셔닝 문장이 깔끔함 | 도메인(salpi.kr 등) 사용 가능 여부 미확인 → 사업화 단계에서 확인 |

### 8-3. 대안 이름 (살피를 안 쓸 경우)

| 이름 | 뜻 | 평가 |
|---|---|---|
| 살피장 | 살피 + 장(시장·장보기) | 식자재 느낌이 바로 남. 캐릭터 연결 유지. 1순위 대안 |
| 시세살피 | 시세 + 살피 | 기능이 가장 명확하지만 '발주(얼마나)' 기능이 이름에서 빠짐 |
| 발주살피 | 발주 + 살피 | 핵심 기능 명확, 다소 딱딱함 |
| 스마트 발주 | 기존 시안 이름 | 일반 명사라 상표·검색에서 구별이 어려움 → 비추천 |

> 판단 기준: 앱 이름은 **기억(캐릭터 연결) > 의미 전달 > 검색 구별성** 순으로 봤습니다. 의미 전달 약점은 설명어로 보완할 수 있지만, 캐릭터와 이름이 따로 놀면 보완이 어렵습니다.

## 11. 살피 AI 에이전트 설계 — 필수 내용 · 필수 데이터

### 11-1. 에이전트가 하는 일 (한 문장)

> 매일 아침, 우리 가게의 **판매 예측 → 메뉴 원가율 → 발주량 → 메뉴 결정**을 한 장으로 브리핑하고, 사장님 질문("제육 가격 올려야 해?")에 **도구로 계산한 숫자만으로** 답하는 에이전트입니다.

### 11-2. 구조

```
[데이터 수집 (매일 06:00)]
 aT 도매 경락가·반입량 / KAMIS / 기상 예보 / 특일·대구 행사
 우리 가게: 판매량(POS·배달앱) / 영수증 OCR 실구매가 / 재고
          │
          ▼
[계산 도구 (숫자는 여기서만 만든다)]
 ① 메뉴 수요 예측 ② 레시피 → 식자재 환산 ③ 메뉴 원가율 계산
 ④ 발주량 추천 ⑤ 기다리기 판단 ⑥ 추천 이유(기여도) ⑦ 메뉴 액션 제안
          │
          ▼
[살피 에이전트 (LLM)]
 브랜드 스킬 + 판단 원칙 + 가게 프로필 + 세그먼트 정책
 → 도구 호출 결과를 사장님 말로 번역, 우선순위 정하기, 질문 응답
          │
          ▼
[출력] 아침 브리핑 카드 / 알림 / 구매처 딥링크 (주문은 사장님이 직접)
```

**핵심 원칙: LLM은 숫자를 만들지 않습니다.** 예측·원가율·발주량은 전부 계산 도구가 만들고, 에이전트는 그 결과를 고르고 설명만 합니다. 숫자를 지어내는 오류(환각)가 원가 판단에 들어가는 것을 막기 위해서입니다.

### 11-3. 에이전트에 반드시 들어가야 할 내용 (시스템 프롬프트 / 컨텍스트)

| # | 필수 내용 | 구체적으로 | 왜 필수인가 |
|-|------|--------------------|-----|
| 1 | **역할 정의** | "대구 외식업 사장님의 메뉴 원가·발주 비서. 아무것도 팔지 않는다" | 중립성이 핵심 차별점 |
| 2 | **판단 원칙** | ① 숫자는 도구 결과만 인용 ② 예측은 항상 범위와 함께 ③ 범위가 넓으면 "확실하지 않아요" 먼저 ④ 특정 판매처 구매 유도 금지 ⑤ 사지 않는 것이 유리하면 "기다리기"를 말한다 | 신뢰·중립 |
| 3 | **브랜드 스킬** | 6장 `SKILL.md` 전체 (톤, 금칙어, 소품 색 규칙, 대사 예시) | 말투 일관성 |

| 5 | **고객 세그먼트 정책** | 3장 S1~S5별 먼저 말할 것·알림 빈도 | 알림 피로 방지 |
| 6 | **도구 목록과 사용 조건** | 11-4 표. "원가 질문 → ③ 먼저 호출" 같은 순서 규칙 | 정확한 계산 경로 |
| 7 | **출력 형식** | 아침 브리핑 = 최대 3개 카드(예측·원가 경고·발주), 카드당 정보 1개 + 행동 1개 | 30초 안에 결정 |

| 9 | **모를 때의 행동** | 데이터 부족(판매 기록 2주 미만 등) → 예측 대신 "기록이 쌓이면 알려 드려요" + 업종 평균 참고치 표시 | 콜드스타트 |
| 10 | **피드백 반영** | 별점·"너무 많았어요" 응답을 다음 예측 보정에 기록 | 정확도 개선 |

| 메뉴별 판매량 | 날짜, 메뉴, 판매 수량, 홀/배달 | POS 연동(사업화) · 배달앱 정산 CSV · 직접 입력 · 시연은 가상 매장 | **필수** |
| 실구매가 | 구매일, 거래처, 품목, 수량, 단가, 합계 | **영수증 촬영 → OCR** (CLOVA 영수증 OCR은 품목명·수량·단가·총액 추출) | **필수** |
| 재고 | 품목별 현재고, 다음 입고일 | 발주 전 "남은 양" 간단 입력 | **필수** |
| 소진·폐기 기록 | 품목, 시각, 폐기 kg | 버튼 1번 입력 | 선택 (성과 측정에 필요) |

### 13-3. Claude Design 프롬프트

첫 사용 순서: ① 새 프로젝트 생성 → ② `SKILL.md`, 캐릭터 시트, 칠판 이미지 업로드 → ③ 아래 프롬프트 입력 → ④ 결과를 대화로 수정 → ⑤ PDF 또는 이미지로 내보내기.

**프롬프트 A — 앱 메인 화면**
```
첨부한 SKILL.md의 '살피' 브랜드 규칙(색·톤·금칙어)을 그대로 따라서
모바일 앱 '살피'(메뉴 원가 관리 AI)의 아침 메인 화면을 디자인해줘.

대상: 대구 한식당 사장님(50대, 엑셀은 부담, 카카오톡은 익숙)
화면 구성 (위에서 아래로):
1. 상단: 살피 캐릭터(이마에 손 얹은 포즈)와 인사 "사장님, 오늘 시세 살펴왔어요"
2. 내일 메뉴 예측 카드: 김치찌개 120그릇(95~148), 제육볶음 80그릇(62~101), 된장찌개 60그릇(45~77)
3. 오늘의 발주 추천: 돼지고기 12kg, 양파 9.1kg, 두부 45모 — 각 줄에 "왜?" 버튼
4. 원가율 알림 카드: 제육볶음 원가율 32% → 36%, 원인 "양파 도매가 2주 연속 상승"
5. 영수증 촬영 버튼: "오늘 영수증 찍기" (찍으면 원가율 자동 갱신)
6. 하단 버튼: "판매처 검색하기" (특정 판매처 강조 금지)
수치는 모두 가상 예시라고 작게 표기.
큰 글씨(본문 16px 이상), 한 화면에 결정이 끝나게.
```

**프롬프트 B — 수정 요청 예시**
```
"왜?" 버튼을 누른 상태의 화면도 만들어줘.
돼지고기 12kg의 이유를 막대 4개로: 금요일 효과 38%, 비 예보 26%, 최근 2주 추세 20%, 기타 16%.
위에 "필요 18kg − 재고 6kg" 계산식을 보여주고, 살피는 칠판을 가리키는 포즈로.
```

**프롬프트 C — 세그먼트별 알림 3종**

같은 브랜드로 푸시 알림 카드 3개를 나란히 디자인해줘.
