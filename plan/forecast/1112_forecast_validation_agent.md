## 1. 지금 예측이 어떻게 만들어지나 (검증 대상)

| 종류 | 품목 | 가격 기준 | 예측에 쓰는 이유 | 약점 |
|---|---|---|---|---|
| 농산물 | 야채 15종 (`ITEMS`) | 대구 북부도매시장 경락가 (kg당) | 최근 2주 흐름 · **반입량** · 대구 날씨 · 공휴일 · 행사 | 주산지 날씨 · 수입량 없음 |
| 수산물 | 12종 (`EXTRA_ITEMS`) | 북부도매시장 중도매가 / 대구 소매 평균 (KAMIS 조사) | 최근 2주 흐름 · **한 달 평균과의 차이** · 명절 · 김장철 · 행사 | 반입량 · 조업 상황 · 수입량 없음 |
| 육류 | 7종 (`EXTRA_ITEMS`) | 대구 소매 평균 (KAMIS 조사) | 위와 같음 | 도매 경락가 없음 (축산물품질평가원 API 신청 전) |

- 수산물 · 육류는 경매 자료(반입량)가 없어 **이유가 하나 적은 추정**이다. 그래서 더더욱 맞는지 확인이 필요하다.
- 예측 결과는 셋 다 같은 모양: 예상 변화율(%) · 예상 가격 범위(최저 ~ 최고) · 방향 문구(오를 / 비슷할 / 내릴, ±2% 기준).

## 2. 채점표 (셋 다 같은 기준)

| 지표 | 뜻 | 목표 | 왜 |
|---|---|---|---|
| **범위 적중률** | 7일 뒤 실제 가격이 예측 범위 안에 든 비율 | 1단계 70% → 2단계 80% | 화면에 "예상 ○원 ~ ○원"으로 보여 주는 값이라 가장 중요 |
| 범위 폭 | 범위가 평균 ±몇 %인지 | 같은 적중률이면 좁을수록 좋음 | 범위를 넓히면 적중률은 쉽게 오르므로 같이 봐야 함 |
| **방향 적중률** | 오를 / 비슷할 / 내릴 문구가 맞은 비율 (실제 변화 ±2% 기준) | 60% 이상 | 사장님이 실제로 읽는 건 문구 |
| 평균 오차 | 예측 변화율과 실제 변화율의 차이 (%p) | 작을수록 | 공식 고칠 때 비교용 |
| **비교 기준 대비** | "그냥 지금 가격 그대로"(변화 0%)라고 했을 때보다 나은가 | 기준보다 좋아야 함 | 이걸 못 이기면 예측이 의미 없음 |

- 품목별 · 종류별(농산물 / 수산물 / 육류) · 방향별(오를 거라고 한 것만 따로)로 나눠서 본다
- "오를 거예요"라고 했는데 내린 경우가 사장님께 가장 손해 → **오를 예측의 정답률**을 따로 표시

## 3. 검증 에이전트가 하는 일

```
[매일 새벽]  예측 기록 ──▶ forecast_log (예측한 날 · 품목 · 기준 가격 · 예상 범위 · 방향 · 요인별 %)
[매일 새벽]  채점 ────────▶ 7일 전 예측 ↔ 오늘 실제 가격 비교 → 맞음 / 틀림 기록
[매주 월요일] 리포트 ──────▶ 지난 4주 채점표 + 많이 틀린 품목 · 요인 + 고칠 점 제안
```

| 단계 | 하는 일 | 사람 / AI |
|---|---|---|
| ① 기록 | 매일 새벽 모든 품목의 예측을 그대로 저장 (계산 결과 그대로, 나중에 바꾸지 않음) | 코드 (AI 필요 없음) |
| ② 채점 | 7일 뒤 실제 가격을 받아 위 채점표 계산 | 코드 (숫자는 코드로만) |
| ③ 원인 찾기 | 많이 틀린 경우를 모아 "어떤 요인이 반대로 갔나" 정리 (예: 김장철 +2%를 줬는데 굴은 내렸다) | **검증 에이전트 (AI)** |
| ④ 제안 | 계수 조정 · 요인 추가 · 품목 제외 제안을 문서로 | 검증 에이전트 → **사람이 판단해 반영** |

- **숫자 계산은 코드, AI는 설명 · 원인 정리만** (살피 에이전트와 같은 원칙: 숫자는 `analysis.py`에서만 만든다)
- 검증 에이전트는 살피 챗봇과 **따로 둔다**. 사장님 대화 속도에 영향을 주지 않게, 하루 한 번 / 일주일 한 번만 돈다
  ([1111_bm_voc_process.md](../bm/1111_bm_voc_process.md) 7절 서브에이전트 구조 · 주의점 참고)
- 에이전트가 공식을 **스스로 고치지 않는다**. 제안만 하고, 사람이 확인해 반영한다 (틀린 방향으로 계속 고쳐 버리는 일 방지)

### 에이전트 도구 (만들 것)

| 도구 | 하는 일 |
|---|---|
| `get_scorecard(group, weeks)` | 종류별 · 품목별 채점표 |
| `get_misses(item, weeks)` | 많이 틀린 예측 목록 (예측 · 실제 · 요인별 %) |
| `get_factor_check(factor)` | 요인 하나가 맞는 방향이었던 비율 (예: "반입량" 요인이 +일 때 실제로 오른 비율) |
| `compare_baseline()` | "변화 없음" 예측과 비교 |

## 4. 예측 기록 저장 (가장 먼저)

| 칸 | 예 |
|---|---|
| 예측한 날 · 기준 날짜 | 2026-11-12 · 11-10 (마지막 시세 날짜) |
| 종류 · 품목 · 단위 · 가격 기준 | 수산물 · 굴 · kg · 중도매 |
| 기준 가격 | 15,000 |
| 예상 변화율 · 예상 범위 | +3.0% · 14,717 ~ 16,183 |
| 방향 | 오를 가능성 |
| 요인별 % | 최근 흐름 +0.9 · 한 달 평균 +0.1 · 김장철 +2.0 |
| 공식 버전 | v1 (공식을 바꾸면 v2 — 버전별로 따로 채점) |
| (7일 뒤 채움) 실제 가격 · 실제 변화율 · 범위 안? · 방향 맞음? | 15,400 · +2.7% · 맞음 · 맞음 |

- **저장 위치는 Supabase** (판매량 예측에 이미 씀). Vercel은 서버가 새로 켜지면 파일이 사라져서 `cache/`에 두면 안 된다
- 하루 한 번, 새벽 시세가 올라온 뒤 저장 (같은 날 여러 번 저장하지 않게 "예측한 날 + 품목"을 고유값으로)
- 하루 34개 품목 × 1줄 → 한 달 약 1,000줄. 무료 용량으로 충분

## 5. 지난 자료로 되돌려 채점 (백테스트) — 기다리지 않고 바로 해 볼 수 있는 것

기록을 쌓기 시작하면 첫 채점까지 7일, 믿을 만한 숫자까지 4주가 걸린다. 그 전에 **과거 날짜에 "그날 예측했다면?"을 다시 계산**해 본다.

**자료는 이미 저장소에 있다** — `data/raw/1109_5y/` (PR #43, 2021-01-01 ~ 2026-11-08)

| 파일 | 내용 | 백테스트에서 쓰는 곳 |
|---|---|---|
| `1109_price_daily_<품목>.csv` (16개) | 야채 15종 + 쌀, aT 일별 도·소매가 (대구 · 북부도매 중도매 + 소매 5곳) | 중도매가 기준 채점 · 되돌림(1년 평균) · 계절 변화 |
| `1109_wholesale_qty_daily.csv` | 북부도매시장 품목별 하루 거래량(kg) · 거래금액 | **반입량 요인** + 거래금액 ÷ 거래량 = **경락가(kg당)** → 지금 화면과 같은 기준으로 채점 가능 |
| `1109_weather_daegu_daily.csv` | 대구 기상청 일별 (기온 · 비) | 날씨 요인 |
| `1109_wholesale_closed_days.txt` | 도매시장 쉬는 날 | 쉬는 날을 빼고 "7일 뒤" 계산 |
| `scripts/fetch_price_wholesale.mjs` | 위 파일을 받은 코드 (`.env` 키 사용) | 수산물 · 육류 받을 때 그대로 씀 |

| 종류 | 지금 가능한가 |
|---|---|
| 농산물 | **바로 가능.** 가격 · 반입량 · 날씨가 5년 치 다 있음 → 지금 공식(v1)을 2021~2026 전체로 채점 |
| 수산물 · 육류 | **받기만 하면 가능.** 위 스크립트가 쓰는 perDay API는 날짜 범위를 주면 과거도 받아짐 → `ITEMS`에 축산(500) · 수산(600) 코드 19개(`data_sources.EXTRA_ITEMS`)를 넣어 한 번 돌리면 5년 치. 반입량이 없는 공식이라 가격 파일만 있으면 됨 |

- 공휴일은 특일 API · 행사는 과거 자료가 없어 백테스트에서는 **행사 요인을 빼고** 채점한다 (영향이 0~1%라 결과에 거의 차이 없음)
- 주의: 과거 날짜로 계산할 때 **그날 이후 자료를 쓰면 안 된다** (미래를 보고 맞힌 셈). 코드에서 "기준 날짜까지만" 잘라서 넣는다
- 주의: 공휴일 · 행사 · 날씨도 "그날 알 수 있었던 것"만 쓴다
- 결과는 발표 슬라이드 "예측 모델 비교"(1108 문서 1절)에 그대로 쓴다: 지금 공식 vs 회귀 공식 vs 부스팅
