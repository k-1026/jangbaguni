## 2. 학습 방법

| 단계 | 내용 |
|---|---|
| 맞히는 것 | 그날 판매량 ÷ 평소 수준(최근 24 영업일 평균). 예측 = 평소 수준 × 모델 값 → 손님이 천천히 늘어도 덜 흔들림 |
| 요인 12개 | 메뉴 · 요일 · 공휴일 · 평균 기온 · 비 · 폭염 · 삼성 홈경기 · 대구 축제 · 월급날 무렵 · 월 · 같은 요일 비율(최근 8주) · 최근 흐름 |
| 모델 | 그래디언트 부스팅 (시세 예측과 같은 `gbdt.py`), 나무 깊이 2 · 학습 속도 0.05 · 제곱오차 |
| 시험 | 마지막 6달을 28일씩 굴려 가며: 그 달 앞 기록으로만 학습(마지막 28일은 나무 개수 정하는 검증) → 그 달 예측. **같은 날들을 지금 규칙으로도 예측해 비교** |
| 저장 | 시험 뒤 1년 전체로 다시 학습 (나무 258개) → `models/demand_demo.json` |
| 내일 예측 | 날씨는 기상청 예보(평균 기온 · 강수확률 60% 이상이면 비), 홈경기 · 축제 날짜는 모델 파일에, 공휴일은 API |
| 범위 | 검증 기간 "실제 ÷ 예측"의 10% · 90% 지점 (예측의 0.85 ~ 1.16배) → 10번 중 8번 들어오는 폭 |

지금 규칙(`demand.py`): 최근 4주 평균 × 요일 비율 × 공휴일 비율 × 최근 2주 흐름(절반만). 날씨 · 경기 · 축제는 모름

### 읽는 법 · 한계

- **차이가 작은 이유**: 무작위 흔들림(약 ±9%)이 요인 영향(대부분 +5~10%)보다 크고, 1년 치라 홈경기 · 폭염 같은 날이 많지 않음. 메뉴마다 흔들림이 있어서 오차율 9~10% 아래로는 내려가기 어려움
- **삼성 홈경기는 못 찾음**: 배달만 +30%라 전체로는 +9% 정도인데, 흔들림에 묻힘
- **비 요인은 거의 안 씀(3%)**: 가정에서 비는 홀 → 배달로 옮겨 갈 뿐 전체 그릇 수는 거의 같음 → 모델이 맞게 무시한 것
- **가상 데이터의 한계**: 요인의 영향은 팀이 정한 가정이라, 모델이 그 가정을 다시 찾아낸 것이다. 실제 가게에서 얼마나 맞을지는 알 수 없음
- 화면에는 **시연 가게에서만** 학습 모델을 쓰고, 다른 가게는 지금 규칙 그대로

## 4. 화면 · 서버

- `/api/demand` (내일 준비): 시연 가게면 학습 모델로 메뉴별 그릇 수 · 범위 · 이유(그날 해당하는 요인만, 예: "금요일 +16%", "월급날 무렵 +5%"). 모델이 없거나 실패하면 규칙
- 응답에 `model`(버전 · 시험 성적)과 `model_version`(`demand-demo-20261118`)이 붙고, `menu_forecasts` 에도 같은 버전으로 저장
- 화면: "판매 기록 11.17까지 · 학습 모델 (가상 판매 기록)" 표시, 이유 문구 "삼성 홈경기 영향으로 평소보다 9% 많이 팔릴 것 같아요"

## 5. 다시 만들기

```
cd salpi_agent
.venv\Scripts\python -m demand.dummy_store --apply   # 더미 데이터 다시 만들고 Supabase 시연 가게에 넣기 (어제까지)
.venv\Scripts\python -m demand.demand_learn          # 학습 · 시험 · 모델 저장 (약 5분)
```

- 같은 씨앗값이라 몇 번 돌려도 같은 데이터가 나옴 (마지막 날만 바뀜)
- 발표 직전에 한 번 더 돌리면 판매 기록이 그날 어제까지로 늘어남 (안 돌려도 화면은 동작, 판매 기록 날짜만 멈춰 있음)
- `--apply` 는 시연 가게의 판매 기록 · 시연 영수증(source = demo) · 재고를 지우고 다시 넣음. 영수증 읽기로 넣은 영수증(source = ocr)은 그대로
