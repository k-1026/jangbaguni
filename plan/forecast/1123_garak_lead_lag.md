# 가락시장 선행 시차 · 적중률 표 (야채, 11/23 — 대구를 모델이 맞히는 정산 경락가로 다시 계산)

> 무엇: 가락시장 값이 오르내리면 **며칠 뒤 대구 북부도매도 따라 움직이나**를 품목마다 잰 표
> 쓰임: 화면 "이유" 문구 (예: "서울 가락시장에서 애호박값이 올라서 대구도 곧 오를 수 있어요")

## 0. 한 줄 요약

- **대구를 모델이 실제로 맞히는 값(정산 경락가 kg당)으로 바꾸니 선행 효과가 크게 줄었음.** 첫 버전(대구도 perDay 조사 가격) 시험 lift +9 ~ +37%p → 이번 **+2 ~ +13%p**
- 판정 "쓸 만함" 7품목 (무 · 양배추 · 애호박 · 오이 · 상추 · 시금치 · 토마토), "약함" 7품목 (양파 · 대파 · 배추 · 감자 · 당근 · 깻잎 · 청양고추). 이전엔 12품목이 쓸 만함
- **시차가 거의 1거래일**이라 값이 2일 늦게 올라오는 지금 자료로는 화면에서 "앞서 알려 주기"가 어려움 (시차 − 2일 ≤ 0). 시차 5일 · 7일 품목이 줄고 시금치(7일)만 남음 → 불안정
- 앞 문서의 모델 실험(효과 0)과 같은 방향: **가락 선행은 대구 경락가 예측에 크게 보탬이 안 됨**

## 1. 첫 버전과 달라진 점

| | 첫 버전 (11/23 오전) | 이 문서 |
|---|---|---|
| 대구 값 | perDay 중도매 상품가 (KAMIS 조사) | **정산 경락가 kg당 = 금액 ÷ 반입량** (학습 모델과 같은 값, `price/backtest.load_veg` 와 같은 품목 고르기) |
| 가락 값 | perDay 중도매 상품가 | 같음 (경락가 자료는 저장소에 없음) |
| 겹치는 날 | 1,422일 | 1,370 ~ 1,418일 |

## 2. 어떻게 쟀나

| 항목 | 내용 |
|---|---|
| 값 지수 | 가락은 (품종 · 단위)별로 이웃한 거래일 변화(로그)를 평균해 이음. 대구는 하루 한 값(경락가) |
| 신호 | 가락 **3거래일 변화가 +3% 이상 / −3% 이하** |
| 적중 | k거래일(1 ~ 7) 뒤 대구가 **같은 방향으로 ±2% 넘게** 움직임 |
| lift | 적중률 − 기준률(아무 날). 오름 · 내림 평균 |
| 시차 고르기 | 앞 기간(~2025-10-31)의 lift가 가장 큰 시차 → **안 본 마지막 1년(2025-11-01~)** 에서 확인 |
| ΔR² | 대구 자기 3거래일 변화로 설명한 것에 가락을 더했을 때 늘어난 설명력 |

## 4. 주의 · 한계

- **차이가 작음**: "쓸 만함"도 적중이 기준보다 5 ~ 10%p 높은 정도. 사장님께 "가락이 오르면 대구도 오른다"고 말하기에는 근거가 약함
- **신호 겹침 · 시차 선택**: 며칠 연속 오르면 같은 흐름이 여러 번 세어지고 7개 시차 중 최선을 골랐으므로 값은 방향 참고용
- **자료 지연**: perDay는 약 2일 늦게 등록됨 → 쓸 수 있는 앞서감은 (시차 − 2일). 시차 1일 품목은 가락 값을 실시간(경매)으로 받아야 의미가 있음
- **값 정의가 다름**: 가락은 조사가(상품), 대구는 경락가(전 등급 평균) — 같은 정의로 맞추려면 가락도 경락 자료(`1119_garak_veg`, 저장소에 없음)가 필요
- 청양고추는 가락 풋고추와 품종이 달라 참고용

## 5. 다음에 할 일 (제안)

1. 화면 문구(A안)는 **크게 기대하지 않고 보류하거나, "쓸 만함" 품목에 한해 약한 표현**으로만: 예 "서울 가락시장도 오르고 있어요(참고)" — "대구도 곧 오른다"고 단정하지 않음
2. 가락 경락 자료(정산)를 받을 수 있으면 같은 정의로 한 번 더 확인
3. 매일 가락 값 받기(`price/garak_collect.py`)는 문구를 쓸 때만 필요
