## 1. 피드백

### 잘한 점

| 무엇 | 받은 말 |
|---|---|
| 전체 | 잘했다 |
| 성능 개선 | 성능 개선 잘했다. 그록(Grok)은 다른 팀도 적용하면 좋을 듯 |
| 모델 성능 | 기존 다른 모델들보다 좋다 |
| 학습 모델 | 학습 모델까지 제시한 것 좋다 |
| 정답률 공개 | 정답률을 숨기지 않고 공개한 것이 신뢰성 측면에서 좋다 |
| 결제 | 토스 테스트 계정 잘했다 |

### 질문과 답

| 질문 | 발표 때 답 | 할 일 |
|---|---|---|
| 새로 가입하면 나머지 영수증이 뜨면 안 되지 않나? | 더미 데이터를 넣어 둔 것 | 사용자별로 데이터 나누기 (2절 A-1) |
| 영수증 날짜가 옛날 것인지 어떻게 아나? | 영수증에 날짜가 나옴 | — |
| 정답률 70% 이상이면 "예측 정확"인 기준은? | 일단은 임의로 정함 | 기준 근거 정리 + 80% 확인 (2절 B-1 · B-2) |
| 수치들이 정확한 수치인가? | 신뢰성을 높이는 방향으로 하겠다 | 수치 검증 (2절 B-3) |

### 추가 의견 · 보완할 점 (받은 그대로)

1. 사용자별로 DB 분리하기. 지금은 공통으로 다 보이고 있음
2. 모델의 어떤 인자들을 건드렸는지(파인튜닝 등), 그래서 어떤 이유로 기존보다 좋았는지 말해 주면 좋음
3. 사용자별로 원가율을 다르게 설정하고 싶을 수 있음 → 기준을 바꿀 수 있게 제공
4. 재고 관리 단위: 선호도 차이이긴 한데, 어떤 건 소수점 한 자리, 어떤 건 소수점 없음 → 표기를 통일
5. 정답률 80% 이상 나오면 좋겠다. 70% 이상은 확인했고, 80% 이상도 확인해 보기 (고도화)
6. 3번 미만은 "채점 중"이라고 하지 말고 "정확한 예측을 위한 횟수가 부족하다"로 변경
7. 구독제로 바꿨으니, 세웠던 BM에서 어떻게 바뀌는지 장표로 보여 주면 좋겠다
8. 기획이 어떻게 변해 왔는지 일목요연하게 보여 주기 (잘 해 온 것들)
9. 채팅창을 위쪽에서도 움직이게 하고, 최소화 창 기호 넣기
