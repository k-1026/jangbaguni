## 1. 누구의 무엇을 해결하나

| 항목 | 내용 |
|---|---|
| 사용자 | 대구 한식음식점 사장님 (1~2인 운영, 재료를 직접 삼) |
| 푸는 문제 | "메뉴 하나 팔면 얼마 남는지" 모른 채 오르는 재료값을 버팀 (VOC 원가 59% · 언제 살까 7%) |
| 핵심 약속 | 영수증 사진 한 장 → 메뉴별 원가율 → 40% 넘으면 다음 행동 3가지 |
| 원칙 | **AI는 읽기 · 나누기 · 말하기만, 숫자는 계산과 학습 모델만** (AI가 숫자를 만들지 않음) |

## 2. 사용 흐름 (한 줄)

영수증 사진 → 품목 · 양 · 금액 확인 → 메뉴별 원가율 → (40% 이상) 가격 조정 · 대체 재료 · 메뉴 제안 → 다음 7일 시세 · 더 싼 곳 → 아침 알림

## 4. 핵심 기능 규칙 (입력 → 처리 → 출력 → 기준)

| ID | 입력 | 처리 | 출력 | 기준 · 숫자 |
|---|---|---|---|---|
| F1 | 영수증 사진 | 🤖 제미나이가 품목 · 수량 · 단위 · 금액 읽기 → 사장님 확인 · 수정 → 저장 → 원가율 다시 계산 | 품목 줄 (이름 · 양 · 금액 · 재료 짝) | 고친 "영수증 이름 → 재료" 짝은 기억 (`item_aliases`). 목표: 품목 90% · 금액 95% (V5) → **11/24 시연 영수증 20장 · 103줄: 품목 · 금액 100%** |
| F2 | 품목 · 포장 글자 ("500g×2", "1포기") | ⚙️ 규칙 + 환산표 | 기준 단위당 가격 + 정확도 표시 | 무게 kg · 액체 L · 두부 모 · 계란/사리 개. "정확" / "약"(환산표, 10% 안은 비슷) / "모름"(비교 제외). 환산표 = 농산물 표준규격 L 구간 가운데 · KAMIS 조사 규격 |
| F4 | 메뉴 판매가 · 레시피(g) · 재료 단가 | ⚙️ Σ(레시피 양 × 단가) ÷ 판매가 | 1인분 재료비 · 원가율 · 남는 돈 | **원가율 40% 이상** → ① 가격 조정 (40% 아래 되는 값, 500원 단위 올림, 다음 주 예상 원가 반영) ② 대체 재료 (후보가 다음 주 오르면 제외) ③ 원가율 좋은 다른 메뉴. 단가 우선순위: 영수증 → 시세 → 참고 단가 |
| F5 | 영수증 품목 단가 | ⚙️ 우리 가게 평소 단가(앞 영수증 8장 가운데값) · 대구 시세와 비교 | 싸게 / 비슷 / 비싸게 + 이유 | 10% 안쪽 = 비슷해요. 평소보다 비싸도 소매가보다 싸면 "시세가 올랐어요" |
| F6 | 재료 · 산 값 | ⚙️ 판매처 상품을 기준 단위당 가격으로 → 산 값보다 싼 것만 | 싼 순서 목록 | 환산("약")이 섞이면 10% 넘게 싸야 넣음 |
| F8 | 도매 경락가 · 반입량 · 날씨 · 공휴일 · 행사 · 명절 | ⚙️ 직접 구현한 그래디언트 부스팅, 매일 06:00 다시 학습 → 고정 공식보다 나을 때만 사용 | 7일 뒤 오를 · 비슷 · 내릴 + 범위 + 요인별 기여도 | 방향 기준 ±2%. 성적: 정반대 야채 28.2 → 22.8% · 과일 21.8 → 20.5% (11/17 모델, [발표용 정리](forecast/1118_learning_results_pitch.md)) |
| F9 | 그날 화면에 나간 예측 | ⚙️ 저장 → 7일 뒤 실제 가격과 비교 | 방향 적중 · 범위 적중 · 정반대 비율 | 하루 약 40줄, 같은 날 · 품목은 첫 값만 |
| F10 | 판매 기록 · 레시피 · 재고 | ⚙️ 판매량 학습 모델 → 재료 필요량 − 재고 | 메뉴별 내일 그릇 수 · 재료 발주량 · 사기/기다리기 | 시연 가게만 학습 모델, 나머지는 규칙 |
| F12 | 사장님 질문 | 🤖 안내가 담당 고르기 (버튼 = 규칙, 자유 질문 = 가벼운 모델) → 담당이 도구 호출 → 🤖 살피 말투로 설명 | 답 + 근거 숫자 | 숫자는 모두 도구 결과. 섞인 질문은 담당 동시 호출 |
